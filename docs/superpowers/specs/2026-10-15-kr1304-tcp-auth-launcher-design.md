# KR1304 TCP 账号服务与启动器设计

日期：2026-10-15

## 目标与边界

其他电脑上的玩家通过 `BubbleFighter_KR1304_Launcher` 自行注册、登录并启动
`BubbleFighterU.exe`，连接 `BubbleFighter_KR1304_Server`。修改范围限于这两个项目、
部署脚本和相关测试；第一版不修改游戏客户端。`BfLauncher` 仅供分析启动方式与
Frida hook，不复制它针对另一个 `BubbleFighter.exe` 的整份脚本或偏移。

服务器对外使用固定 IPv4 地址。账号接口使用独立 TCP+TLS 端口，游戏和可选的
clan 服务继续使用原有端口与协议。不提供无 TLS 的远程账号接口，也不要求
HTTPS 域名或玩家另行安装 Frida。

## 服务端结构

在现有 Windows 服务进程内增加独立的认证监听器，使用 Schannel 终止 TLS。
启动参数分别指定认证端口、服务端证书指纹、游戏监听端口，以及对外通告的
固定 IPv4 地址；远程部署时监听地址可以是 `0.0.0.0`，但通告给游戏的地址
必须是实际可达的固定 IP。认证监听器与游戏监听器共享现有数据库配置，
复用 `AccountAuthentication` 和 `MySqlAccountStore`，不另建账号表或签票算法。
缺少数据库配置、证书或证书私钥时，启用认证端口的服务启动失败。

认证协议与游戏协议分离：每个 TLS 连接只接收一个有版本号的长度前缀请求，
返回一个长度前缀响应后关闭。帧头为 4 字节网络序负载长度，负载以 1 字节
版本号、1 字节动作或状态码开始；字符串以 2 字节网络序字节长度加 UTF-8
数据编码，成功登录响应另有 8 字节网络序 Unix 秒过期时间。错误响应使用
稳定的 2 字节错误码与有界的中文提示，不回显输入的账号密码。
客户端和服务端均拒绝多余字段、截断帧或超过上限的长度。
协议字段用专门的编码器和解码器处理，
不依赖旧 CNBFSF 加密报文或未引入的 JSON 库。版本 1 支持 `health`、
`register(username, password)` 和 `login(username, password)`。
请求与响应的负载上限均为 4 KiB；未知版本、动作、非法长度、截断报文
和无效 UTF-8 均拒绝。
响应给出稳定的错误码和可显示的非敏感错误信息；登录成功时返回规范化账号、
一次性票据及其绝对过期时间。票据继续使用现有 `BFS1.` 格式、300 秒有效期
和数据库原子单次消费，不更改游戏端登录报文。

注册继续遵守账号 3–32 位 ASCII 字母、数字或下划线，以及密码 12–1024
UTF-8 字节的现有规则。登录的错误信息不区分不存在、被禁用和密码错误。
TLS 握手和请求读取各限 5 秒；认证入口最多同时处理 16 个连接、每 IP
最多 2 个连接。单 IP 在滚动 5 分钟内有 10 次失败登录后暂停该 IP
的登录 60 秒；注册每 IP 每 5 分钟最多 5 次，数据库唯一索引仍负责
防止重复账号。限制在密码派生前检查，避免请求无限占用工作线程或
密码猜测。日志只记操作、
结果和必要的连接元数据，不记录密码、TLS 私钥或完整票据。

## 证书与部署

提供 PowerShell 7 部署脚本，为固定 IP 生成带 IP SAN 的自签名服务端证书，
私钥留在服务端 Windows 证书存储，导出仅含公开证书的文件供启动器打包。
启动器通过该证书建立信任，并校验访问 IP 与证书标识；认证失败即终止连接，
没有明文回退或跳过校验的选项。启动器包中只有公开证书，不包含私钥。
更换服务端 IP 或证书时，重新导出并分发带新公开证书的启动器。

部署文档列出固定 IP、认证端口、游戏端口、可选 clan 端口、监听/通告地址、
端口转发和防火墙配置；不把 `0.0.0.0` 用作客户端连接或重定向目标。
生产打包前需确定固定 IP 并提供公开证书；开发时可用环回 IP 和测试证书。

## 启动器结构与流程

Electron 主进程提供新的 KR1304 认证客户端，使用 Node TLS 和有界二进制
报文，界面进程不直接持有网络 socket。服务器地址及认证、游戏、clan
端口分别配置；去掉旧外部区服列表对登录路径的控制。界面保留注册、登录、
状态及进入游戏的基本流程，但移除 KR1304 服务端不支持的 QQ 绑定、
注册时昵称/角色名、云配置同步和旧服务端响应字段。角色由游戏内原有流程创建。
现有本机账号密码保存仍使用 Electron `safeStorage`；票据只保存在内存中，
不持久化或写入日志。

注册成功后返回登录页。登录成功获得票据并显示进入游戏；启动时必须使用
尚未消费且接近签发时间的票据。过期、已使用或需要重试时重新认证签票；
没有可用的本机凭据时要求玩家手动登录。启动器配置游戏连接至固定 IP
与游戏端口，必要时设置 clan 端口，不把认证端口作为游戏端口。

第一版随启动器封装最小 Frida 运行时与专用 hook，先在目标
`BubbleFighterU.exe` 上验证登录字段的构造位置，再在进程恢复运行前把票据
写入 `0x0003` 登录报文的 `NexonPassport` 字段。只有验证确需重定向时才
增加最小连接重定向 hook；不引入旧脚本的商店、UI、消息或本地 bridge
功能。将票据注入封装在独立边界内，方便以后由客户端内置逻辑替换；
认证协议和服务端票据消费逻辑不依赖 Frida。注入或目标版本检查失败时
结束尚未正确启动的游戏进程并告知玩家，不继续无票据启动。

现有旧服远端更新、白名单和 `hash.md` 校验不再阻断 KR1304 登录与启动。
用随 KR1304 客户端分发的版本清单校验目标 `BubbleFighterU.exe` 及约定的
游戏资源；校验失败明确列出受影响文件，不自行下载旧服文件。清单与
目标客户端版本一同更新。

## 错误与验证

启动器区分证书/IP 不匹配、认证端口不可达、协议不兼容、注册账号重复、
账号或密码错误、票据失效、游戏文件校验失败及注入失败；错误不展示
密码或票据。服务端无法加载证书或数据库时拒绝启动认证端口。

自动测试覆盖二进制协议的边界与截断、TLS 信任和错误证书、注册与登录、
失败限流、票据过期/单次消费，以及服务端同时监听认证和游戏端口。
本机集成测试使用 `BubbleFighterU.exe` 验证注入、登录报文和进游戏流程，
并检查打包后的启动器无需额外安装 Frida。其他电脑的实际联网验收必须
在固定 IP、端口转发和防火墙部署完成后进行；本机通过不等同于远程验收。
